# AI行動改善教訓 (Lessons Learned)

## 1. 計画と確認の徹底（エラー再発時の厳格なルール）
- **事象**: 同じエラーが繰り返された際、焦って推測でファイル書き換えやコマンド実行（環境変数の確認など）を無断で進めてしまった。
- **原因**: 「早く解決しなければ」というAI特有のバイアスが働き、グローバルルールの「計画の確認（Verify Plan）」「問題発生時は立ち止まる」をスキップしてしまった。
- **今後の絶対ルール**:
  1. 予想外のエラーが起きた場合、**一切の変更（コマンド実行、ファイル保存）を行わない**。
  2. なぜ間違えていたのか（前提の崩れ）を言語化する。
  3. 新しい仮説を立て、`tasks/todo.md` を書き直す。
  4. **「この計画で進めてよいか？」とユーザーに明示的に許可を求めるまで、絶対に次のアクション（ツールの実行）を起こさない。**

## 2. デバッグ時の変数分離（One by Oneの原則）
- **事象**: バグの解決策として、「サーバー側（LiteLLM）の修正」と「手元（opencode.json）の修正」の2つを同時に適用してしまった。
- **原因**: 考えうる解決策を一度に全て試すことで、早く解決しようとしたため。
- **今後の絶対ルール**:
  1. バグ調査や修正を行う際は、**必ず1つずつ変更を加え、その都度結果を検証すること**。
  2. 複数の変更を同時に行うと「どれが真の解決策だったのか（またはどちらも必要だったのか）」が不明になり、技術的負債や無意味な設定を残す原因となる。
