# ローカル開発＆デプロイ運用ガイド

## 1. 開発ワークフロー（基本方針）
このプロジェクトは、「手元のWindows PCでコードを編集し、リモートの推論サーバー（192.168.50.112）にデプロイする」スタイルを基本とします。

1. **手元で編集**: VS Codeなどでこのフォルダ内のファイルを編集・保存します。
2. **ワンクリックデプロイ**: ターミナル（PowerShell）で `.\deploy.ps1` を実行します。
   - 単なるファイル同期だけでなく、サーバー側のDockerコンテナも再起動して変更を完全反映させたい場合は `.\deploy.ps1 -Restart` と打ちます。

## 2. SSH接続の仕組み
デプロイ（同期）の裏側ではSSH通信が行われていますが、**毎回手動でつなぐ必要はありませんし、パスワードを聞かれることもありません。**
`deploy.ps1` を実行した瞬間に、裏側で自動的にSSH接続が開き、数秒で差分ファイルだけを転送して自動で切断されます。

### 【重要】Windows標準SSHのバグとWSLによる回避（今回の苦戦の備忘録）
今回、サーバーへのSSH接続で大苦戦した原因と解決策の備忘録です。将来PCを買い替えた際などに役立ててください。

- **原因**: Windows標準搭載のOpenSSHクライアント（`ssh.exe`）に、「サーバーが鍵を受け入れた直後、署名パケットを正常に送れずに無言で通信を切断してしまう」という特有のバグがありました。
- **解決策**: Windows標準のSSHを完全に捨て、Windows内のLinux（WSL/Ubuntu）に搭載されている「Linux純正のOpenSSH」を経由させることで完全にバグを回避しました。
- **現在の状態**: すでにWSL内に認証用の秘密鍵（`~/.ssh/id_ed25519`）を配置し、サーバー側（192.168.50.112）にも登録済みです。そのため、現在は何もしなくても安全・確実に通信できます。

## 3. 手動でサーバーに入りたい場合
Dockerのログを見たり、サーバーのGPU使用率を直接確認したい場合は、PowerShellを開いて以下のコマンドを打つだけで、パスワードなしで一発でサーバーの中に入れます。

```bash
# WSL（Linux）の純正SSHを経由してサーバーに接続する魔法のコマンド
wsl ssh abtr1094@192.168.50.112
```

（※**注意**: 必ず頭に `wsl` をつけてください。これを忘れて単に `ssh abtr1094...` と打つと、バグのあるWindows標準SSHが起動してしまい、エラーで弾かれます）
